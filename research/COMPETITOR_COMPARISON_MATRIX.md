### What the interaction evidence says

- PDF24, iLovePDF, Smallpdf, and PDFgear present a direct file-selection/drop state at the merge route. The density and visual language differ; Folioyard should borrow neither layout nor assets. Adobe's page was denied in REA, so its merge UI is documented from Adobe's public help page only.
- iLovePDF documents the clearest thumbnail workflow: source files are visually grouped, pages can be removed by selecting thumbnails, and the chosen pages can be exported as one PDF or a ZIP. PDF24 and Smallpdf also document page-level rearrangement.
- For this milestone, the useful common pattern is a visible ordered source list, explicit page/document counts, a real preview, and a clear output action. The MVP will use keyboard-operable move-up/down controls; it will not add drag-only interaction.
- “Sign” is not one uniform capability. A placed signature image, an e-signature request/audit trail, and a certificate-backed digital signature are different products. Folioyard must name each one accurately if added later.

## File handling, account boundaries, and performance

| Product | Published file-handling model | Access/limits described by vendor | Evidence boundary |
|---|---|---|---|
| PDF24 | Online tools upload documents over encrypted transfer; vendor says processing servers are in the EU and files are removed within one hour. Windows PDF24 Creator is the offline/local alternative. | Vendor advertises free use without registration or use-count limits. | Published statements; no file sent. REA observed only the entry page. |
| iLovePDF | Online processing uses upload/cloud workflows; vendor help says output retention depends on account type, with automatic deletion. Its security help says most output files are deleted within two hours; Sign is a distinct retained workflow. | Free/account tiers have operation-specific limits; Premium advertises unlimited processing. Device, Google Drive, and Dropbox routes are documented. | Published statements; no account, cloud integration, or retention window tested. |
| Smallpdf | Vendor states TLS transfer and automatic deletion from servers after one hour for most tools. Pro File Storage is an optional persistent cloud area. | Help lists limited access to 21 tools and up to two conversions per day for non-registered/free users; Pro unlocks unlimited tools and selected advanced features. | Published statements; conversion quota should not be generalized to every operation. No file sent. |
| Adobe | Merge help says files are handled by Adobe servers and deleted unless the user signs in to save. | Merge is published as free; cap is 100 files/1,500 total pages/500 pages each. Individual page organization requires sign-in. | Documentation only for this task because the REA browser received access denied. |
| PDFgear | Merge page and secure-tools pages claim browser-local processing with no document-content upload. The broader catalog mixes tools and apps; local handling should be verified operation by operation. | Merge page claims free use without sign-up or size limits. Vendor warns large PDFs/lists can require more device memory and time. | REA observed third-party consent/analytics network activity on the entry page, before any file selection. This does not contradict a claim that PDF contents stay local, but it means the page itself is not network-silent. Document transfer was not tested. |

No comparative processing times, throughput, mobile usability, or output-integrity measurements were made. iLovePDF explicitly attributes upload/processing time to connection, file size, and service load. PDFgear warns that large documents/lists use more device memory and time. These are vendor-described constraints, not Folioyard benchmarks.
